# 査読レポート: 「記号層に接地された LLM エージェント」(ドラフト v0.6)

*査読日: 2026-07-13。査読者: 独立コンテキストの査読エージェント(本セッションの実験経緯を知らない状態で docs/paper-draft.md v0.6 を精読し、主要数値を results/*.jsonl から独立に再計算)。*

**査読方式について**: 本文の主要数値を `results/*.jsonl` から独立に再計算した(MetaQA 全条件の EM・ホップ別値、McNemar 3 対、監査 48 run の P/R、4c の全セルと Fisher 検定、回復 126+126、摂動版、B1p の gold-in-context 分解、表1・2・6・7、kb_verify 使用率、C2f null 経路、3条件 union)。結果は大部分が正確に一致した — この分野の投稿としては例外的に検証可能性が高い。ただし食い違いも複数見つかった(Major 3、Minor 数件)。

## Summary

著者らは、LLM を「理解と記号表現への定式化」に限定し、事実の保存・推論・検証を決定論的記号層(RDF+OWL-RL / CSP / Z3)に委ねるエージェント `nsai` を構築した。中心的主張は、記号層の寄与の符号を決めるのは層の有無ではなく**結合様式**である、というものである: MetaQA(600 問)で記号ツールを任意の道具として与えた条件(EM 0.790)は純ニューラル agentic-grep ベースライン(0.860)に負けるが、同一の記号能力を出力経路上の必須ゲート(回答バリデータ + verify-before-FINAL)に転換すると 0.970 に達する(McNemar 66/0)。補助的証拠として、(a)矛盾 KB 上の自由な OWL-RL 推論器アクセスが擬似違反を増幅して Precision を 0.05 に崩壊させ、閉包前の違反列挙ゲートで 24/24 run P=R=1.0 に回復すること、(b)LLM 判定者による検証追加は矛盾仕様の誤完了宣言を有意に減らさないこと(ネガティブコントロール)、を提示する。RQ1(主張判定)と 4a(SMT によるバグ修正)は null であることを明記している。

## Strengths

- **数値の検証可能性が非常に高い。** 抜き取りでなくほぼ全数を生データから再計算したが、表0–8 の主要値、McNemar/Fisher の p 値、監査 48 run の per-run P/R、B1p の分解(.926/.118、3-hop gold-in-context 63%)、kb_verify 使用率逆転(49/27/12%)、ビット同一予測集合(86/393/145 件)まで一致した。
- **「ツール vs ゲート」という問いの立て方が新しく、結果が明確。** rev5 vs B2 = 66/0、rev5 vs rev2 = 108/0(改良の一方向性)は再計算で確認。誤り分析 → ゲート設計 → 失敗 126 問中 106 回復・対照 126 問退行ゼロ、という一巡は説得力がある。
- **ベースライン設計が誠実。** B2(agentic-grep)は多くのニューロシンボリック論文が置かない「最も強い非記号ベースライン」であり、これに C1 が負けるという不都合な結果を主結果に昇格させた判断は高く評価する。B1p の gold-in-context 分解も検証上限の分析として的確。
- **null 結果の明示。** RQ1 の飽和、4a の plain≒nsai、委譲の非優位、を abstract レベルで報告している。C2f の生存バイアス(0.862 という誤った推定を自ら棄却)の記述は方法論的に価値がある。
- **監査実験の機構分析(推論器の中毒・逐語転記)は本論文で最も独創的な知見。** 「決定論は誤りを増幅して固定する」という観察は、ゲートテーゼの対偶として綺麗に位置付いている。per-run データで双峰性・ビット同一性とも確認できた。

## Major concerns

**M1. 中心主張の評価がゲート設計に使った同一の 600 問上で行われている(適応的過学習の危険)。**
S1 の「起点除外検査」は C1-rev2 の同じ 600 問での失敗分析(3-hop 失敗の 93% が起点属性誤読)から設計され、rev5 の見出し値 0.970 はその同一 600 問で測られている。対照 126 問は「退行しない」ことしか担保せず、ベンチマーク固有の規約への過適合(著者自身が §1.1・§7 で「起点除外は MetaQA の解答規約由来」と認めている)を排除しない。MetaQA には数万問の未使用問題があるのだから、**開発に一切使っていない新規サンプル(例: 各ホップ 200 問)での rev5 の再測定**が必須である。摂動版も rev2 系でしか走っていない(results-summary でも rev5 摂動は「未実施」)。これが解消されない限り、0.970 という数字は「開発セット上の値」として割り引いて読まざるを得ない。

**M2. Abstract・貢献4・§4.3・§5.3 の「真の違反 19 件が 95 件に」は生データと整合しない。**
再計算: a500c5 の gold(注入矛盾)は **5 件**であり(`data/a500c5/injected.jsonl` = 5 行、`audit-a500c5-*` の gold フィールドも 5 件)、崩壊 run の Precision 0.05 ≈ **5/95** としてのみ整合する(19/95 なら P=0.2 のはず)。さらに rev4 の `kb_violations` は正確に 5 件を返して P=R=1.0 を達成しており、「基底 KB の真の違反が 19 件」なら rev4 の P=1.0 と矛盾する。「19」は内部ノート(design-revision-plan.md)由来のまま残存したと推察する。大グリッドの「20→393」は正確である(gold=20、pred=393 を確認)。**Abstract に載る数値**なので必ず修正すること(5→95、増幅率も 19 倍から修正)。

**M3. C1-rev5 と B2 の間で開発努力が非対称であり、「決定論的ゲート」と「強制された出力検査プロトコル一般」が MetaQA 上で分離されていない。**
B2 は rev2 のまま据え置かれ、記号条件だけが失敗駆動で 3 版の改良を受けた。「FINAL 前に候補を KB 生テキストに対して grep で再確認せよ」という**ニューラル版ゲート**(B2 + 強制再検査契約)のアブレーションがあれば、利得のうち「プロトコル強制」由来と「決定論的検査」由来を分離できるが、これが無い。§4.4 のネガティブコントロールは別ドメイン(コーディング完了判定)・別タスク・n=20 であり、MetaQA の主張を直接には支えない。存在検査・型照合は grep でも近似実装できる以上、このアブレーションなしに「有効成分は決定論性」と結論するのは飛躍がある。**B2+ゲート契約の 1 条件を追加するだけで貢献1の主張は大幅に強化される。**

**M4. ネガティブコントロール(4c)は検出力不足であり、Abstract の断定はデータより強い。**
再計算で 19/20 vs 15/20、片側 p=0.0909 を確認した。しかし n=20/セルでは 20 ポイントの改善(95%CI はゼロを跨ぐが広い)すら検出できない。「有意に減らない」から「ゲートの有効成分は決定論性であってセカンドオピニオンではない」(Abstract、§8)へ進むのは、検出力の裏付けのない null からの過大な推論である。加えて、初期 5 問で分離(5/5 vs 3/5)を見た後に 15 問を追加した逐次的デザイン(`coding4c-*-inf15.jsonl` のタイムスタンプは主結果の後)であり、中間解析への補正がない。対処: (i)n を増やす、(ii)検出力分析と信頼区間を併記し主張を「n=20 では判定者の利得は検出されず、効果があるとしてもモデル間差(p=2.9e-08、これは頑健)より一桁小さい」に弱める、(iii)逐次デザインを明記する。

**M5. 見出し条件が単一 run であることは、本論文自身の証拠によって危うくされている。**
監査実験は、同一条件・同一 KB で run 間に P=1.0 と P=0.05 が混在する双峰性を示した — つまり本論文は「エージェント系の run 間分散は極めて大きくなり得る」ことを自ら実証している。にもかかわらず MetaQA の中心比較(rev5 0.970 vs B2 0.860)は各条件 1 run である。McNemar は項目レベルの対応を扱うが、条件あたり 1 本のサンプル軌道に条件付けられている。66/0 という差が run 分散で消えるとは考えにくいが、rev6 vs rev5(p=0.30、Δ=5問)のような微差の解釈は 1 run では危うい。最低限、rev5 と B2 の 2 条件だけでも 3 run 化し、run 間の EM 変動幅を報告すべきである。

**M6. 表4 の B2 行「原版との差 −.063」は分母の異なる集合を比較している。**
再計算: 摂動 B2 は 300 問(各ホップ 100)であり、−.063 は「摂動 300 問の .797」と「原版 600 問の .860」の差である。**同一 300 問に揃えた対応あり比較では原版 .833、差は −.037**(ホップ別: 1-hop −.090、2-hop +.140、3-hop −.160)。頑健性という結論自体は保つが、表の数値は誤解を招く。マッチした部分集合で再掲し、B2 のみ 300 問である理由も本文に明記すること。

**M7. §4.2/§5.2 の C2f null の機構記述が生データと食い違う。**
再計算: pred=null は 51 件で一致するが、「`tool_calls={Task:1}` のまま」は不正確 — 実データのキーは `Agent` であり、Agent 1 回のみは 23/51、残り 28 件は kb_find/kb_sparql/kb_stats 等を併用、2 件は Agent 2–3 回。ハンドオフ喪失という結論は保つが、記述は実測に合わせて修正すること。同様に §4.3 の「318 回のツールコールと $15.51」は、当該 run の総ツールコールが 343 回(うち kb_provenance が 318 回)である。「318 回の provenance 照会を含む 343 ツールコール」が正確。

## Minor issues

- **rev6 vs rev5 の判別対「10/5」の順序**: §3.3 の定義(n10 = 条件 A のみ正解)に従い A=rev6 とすると 5/10 である。p=0.302 は一致するが、統計を担う文なので表記を定義に揃えること。
- **「コスト約 1/75」の分子の選び方**: $15.51 は rev2 の最悪(修復戦略)run であり、rev4 平均 ~$0.2 との比較はワーストケース対平均。rev2 グリッド平均($1.03–10.13)対 rev4 平均も併記するのが公正。
- **再現性の記述と実データの齟齬**: 冒頭で「正誤キーは `correct`」と宣言するが、4a は `passed`、4c は `declared`/`early_completion`/`feasible`、監査は gold/pred 集合であり、`correct` キーは存在しない。スキーマの節を Appendix に置くこと。また 4c の tier ラベル(original/direct-example/…)は JSONL に記録されておらず、表8 の tier 別列は生データから検証不能である。
- **C2f の最終値の会計**: 0.825 = (473+22)/600 だが、再々走の 5/12 を算入すれば 500/600 = 0.833 になる。どの再走までを本則とするかの規則(かつ他条件に同じ救済を与えない非対称性)を明文化すること。
- **表7 の tests/課題は valid スイートのみの平均**(全体平均は 14.3/15.8)— 脚注で明示を。
- Abstract が長すぎ、貢献リストと重複が多い。§4.0(パイロット)は「主張の根拠に用いない」と言いつつ 2 図を占有しており、Appendix へ。
- 主結果(はしご、rev 系譜、監査の崩壊→回復)に図がない一方、パイロットにだけ xychart がある。はしご図 1 枚で §4.2 の可読性が大きく上がる。
- 貢献1 の「我々の知る限り初」: 制約付きデコーディングや verifier-gated generation(生成物が検証器を通過するまで出力しない系)は「ゲートとしての結合」の近縁であり、related work での言及と主張の限定(「エージェントループにおける同一記号能力のツール/ゲート統制比較として初」)を勧める。
- FVR を形式定義(§3.3)までして結果が全条件 0.000 の一行のみ — 定義の重みと結果の軽さが不均衡。
- 投稿先はいずれも英語会議であり、英語化時の用語統一(「取り付け方」= attachment/coupling mode 等)を早めに固めること。

## Questions to authors

1. **「19 件」の出所は何か?**(M2)生成器のどのカウントか、それとも旧ノートの転記ミスか。
2. rev5 のプロンプト・ゲート仕様は、全 600 問再走の**前に**凍結されたか? 失敗 126 再走 → 対照 126 → 全 600 のどの時点で何を変更したか、タイムラインを示せるか。
3. rev5 を摂動版・未使用の新規 MetaQA サンプルで走らせない理由はあるか(コスト以外に)。
4. B2 に verify-before-FINAL 相当の契約(grep による存在・最終ホップ再確認)を課した場合の予備データはあるか(M3)。
5. 4c の tier 設計は初期 5 問の結果を見た後か(逐次検定の懸念、M4)。
6. `kb_check_answer` の型照合・存在検査は KB スキーマにどの程度依存するか — MetaQA 以外の KB に無改変で移植できる実装か。

## Overall assessment

**Weak reject**(confidence: **4**)— 数値の信頼性と問いの新しさは一流会議水準だが、中心主張(0.970)がゲート設計に使った同一問題集合上でのみ測定されており、かつ「決定論的ゲート vs 強制検査一般」を主戦場(MetaQA)で分離するアブレーションを欠くため、現版のままではテーゼの証拠が主張の強さに届かない。M1・M3 が解消されれば accept 圏に入る、修正価値の高い論文である。

## 採択に向けた優先順位付き修正リスト(上位5件)

1. **未使用 MetaQA 新規サンプル(+摂動版)での rev5 の held-out 再測定**(M1)。中心主張の成立可否を決める最重要項目。
2. **B2 + 強制検査契約(ニューラル版ゲート)のアブレーション追加**(M3)。「決定論性が有効成分」という主張を MetaQA 上で直接支える。
3. **Abstract 級の数値誤りの修正**: 19→95 を 5→95 に(M2)、表4 B2 行をマッチ部分集合に(M6)、Task/Agent・318/343・判別対 10/5 の表記(M7、Minor)。
4. **rev5・B2 の複数 run 化(≥3)と run 間分散の報告**(M5)。監査実験の双峰性が単一 run の危うさの内部証拠になっている。
5. **4c の主張の弱化または増強**: 検出力・CI の明示、逐次デザインの開示、可能なら n 拡大; Abstract の「有効成分は決定論性」を「n=20 では判定者の利得は検出されなかった」に整合させる(M4)。
