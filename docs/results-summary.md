## RQ2 — 規模とマルチホップ QA(実験2)

### 合成スイープ(s100–s5000、claims+QA、sonnet/haiku)

- **精度では B1(全文インライン)は劣化しない**(QA 0.938–1.000)。文脈崩壊仮説は
  5000 triples までは不成立。
- **コストが決定的に分かれる**: B1 は線形増加(sonnet $1.5→$45、haiku $0.7→$17)、
  C1 はフラット($1.5 前後)、C2 もフラット($2.3–2.5 / haiku $0.84–0.89)。

### MetaQA(133,582 triples、600 QA、EM 1/2/3-hop)

| 条件 | 原版 | 全体 | コスト | 摂動版 | 全体 |
|---|---|---|---|---|---|
| B0 | .360/.110/.110 | .193 | $5.92 | **.000/.000/.000** | .000 |
| B1p(oracle-BFS+one-shot) | .940/.945/.585 | .823 | $126.54 | (スキップ) | — |
| B2(agentic-grep) | .935/.810/.835 | .860 | $22.28 | .810/**.940**/.640 | .797(300問) |

| C1-rev6(+kb_path) | .950/.990/.945 | .962 | $37.53 | 未実施 | — |

主要な知見:

1. **汚染プローブ決定打**: 実体名を一意 ID に置換すると B0 は完全崩壊(0.000)、
   記号条件は全体 EM ほぼ不変 → B0 の正解は記憶由来、C1/C2 は本当に KB を検索している。
2. **摂動版 B2(レーンB、300問)も頑健**: 全体 .797 で原版 .860 からの低下は小幅。
   hop 別 .810/.940/.640 は C1/C2 の摂動版と同じ「2-hop が最高・3-hop が最低」の
   満足化パターンを再現 — agentic 検索も記憶でなく KB 探索で解いている。
3. **文脈の壁を破るのはエージェント性であって記号接地ではない**: B1p の 3-hop は
   gold-in-context 63% の構造的上限で 0.585 止まり。反復探索できる条件(B2/C1/C2)は
   壁を破る。**ただし rev5 で記号条件が B2 を明確に逆転**(下記レーンF/全600 再走)。
4. **2-hop の失敗モードは実体リンク曖昧性**: 摂動(一意 ID 化)で C1 +0.245、
   C2 +0.155 と 2-hop だけ大幅改善(両条件で再現)→ 原版の 2-hop 低下は経路追跡でなく
   同名実体の曖昧性解消の失敗。
5. **C2f の 0.788→0.825 補正(レーンD)**: 当初報告の「非 null 正解率 0.862」は
   **生存バイアス**(null 51 件を分母から除外した値 = 473/549)。H1 修正(rev3)で
   null 51 件を再走すると 22/51 正解・残 null 12(→再々走で 5/12)。null 補正後の
   EM は (473+22)/600 = **0.825 ≈ C2 (0.828) < B2 (0.860)**。
   「委譲は QA では精度・コストとも損」の結論は不変。

## RQ3 — 矛盾監査(実験3、a500/a2000 × c5/c20 × 3 run)

| 条件 | Precision | Recall | コスト/run |
|---|---|---|---|
| B1 | 12/12 run で P=R=1.00 | 同左 | $0.7–2.2 |
| C1(rev2) | 双峰(1.00 or ~0.03–0.05)、12 run 中 7 で崩れ | ほぼ 1.00 | $3–30 |
| C2(rev2) | 双峰(12 run 中 4 で崩れ) | ほぼ 1.00(1 run 0.35) | $0.7–1.8 |
| **C1/C2(rev4、レーンE)** | **4グリッド×2条件×3 run = 24/24 で P=R=1.00** | 同左 | **$0.11–0.43(平均 ~$0.2)** |

- ≤2000 triples では B1 が完勝だったが、**rev4(kb_violations ツール)で C1/C2 も
  全 run P/R 1.0 に到達**(旧 C1 の最悪 P は 0.00–0.05)。過剰列挙は「検出結果の
  定式化を LLM がやり直す」設計の問題で、違反列挙を記号層に閉じると消える。
- コストも $3–30 → ~$0.2/run に激減(検索の試行錯誤が不要になったため)。
- 「誤りは定式化・報告層に局在し、記号層自体は健全」の直接実証になった。

## RQ4 — ハイブリッドコーディング(実験4)

- **4a(バグ修正)**: sonnet は QuixBugs plain 31/31 vs nsai 30/31、bugsuite 30/30 vs
  30/30 で分離なし。**haiku 追試(レーンC)も同点**(QuixBugs 29/31 vs 29/31、
  bugsuite 30/30 vs 30/30)— 天井は haiku でも降りず。
- **4b(テスト生成・変異検出)**: 分離は **suite validity** で出た —
  EvalPlus llm 80% vs testgen 95%、bugsuite llm 50% vs **testgen 100%**。
  有効 suite 上の kill 率は同等(0.930–0.972)。testgen は 12–14 倍コスト。
  - EvalPlus の 0.73 天井は**等価変異体**が原因(HE-39 の生存 17 = oracle 等価 17)。
    plus-tests killability oracle で正規化すると全セル 1.000。判別軸は bugsuite。
- **4c(完了宣言プロトコル)**: sonnet は self と loop-judge が完全一致で天井。
  **haiku 追試(レーンC)で分離が出た**: hidden は両者 30/30 だが、実行不能 5 課題で
  **self は 5/5 早期完了(STALLED 検出 0)vs judge は早期完了 3/5 + STALLED 検出 2/5**。
  外部判定者は宣言の過信を部分的に抑制する — 天井を降ろすと judge の価値が現れる。
  コスト self $1.28 vs judge $3.15(2.5 倍)。

## 論文の主張構造(rev5 後の確定版)

1. 汚染プローブ: 記憶ベース性能は摂動で消える。記号接地(と agentic 検索)は残る
   (B2 摂動 .797 で agentic 検索の頑健性も確認)。
2. 文脈上限は one-shot の構造問題で、**エージェント性**が破る(B1p→B2)。
3. **記号ツール + 検証契約(rev5)は agentic-grep を EM でも上回る**
   (0.970 vs 0.860、McNemar 66/0 p=2.7e-20)。EM 上乗せの源泉はツールでなく
   「FINAL 前の機械検証を強制する契約」(S2 の記号トラバーサル追加は効果なし)。
4. 記号層の固有価値: (a) **コストのフラット性**、(b) **検証可能性**
   (kb_check_answer / kb_violations による機械検証)、(c) **ソルバー由来テストの
   validity**(4b)、(d) **定式化の記号層への閉じ込めで監査 P が 0.05→1.0**(レーンE)。
5. 委譲はタスク依存: QA では精度・コストとも損(C2f、null 補正後 0.825)、
   監査ではコスト優位(C2)。
6. 誤りは定式化・報告層に局在し、修正可能(レーンE/F で実証)— 記号層自体は健全。
7. RQ1(推論必須タスク)は現合成データでは全条件天井で検証不能 → 推論深度
   スケーリングへの再定式化が必要(限界として明記)。
