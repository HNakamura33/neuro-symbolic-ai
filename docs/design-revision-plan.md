# 設計修正案と実験続行計画(2026-07-11)

起案: 2026-07-11。根拠は results/*.jsonl の全件エラー分析(トランスクリプトなしで
pred/gold/tool_calls から分類、KB 照合で機械検証)と src/nsai・experiments/harness.py の
構造調査。issue #8 の方針を実データで一段具体化したもの。

## 0. エラー分析の新事実(設計修正の根拠)

既存の結果サマリ(docs/results-summary.md)の解釈を **4 点更新**する:

1. **MetaQA 3-hop の失敗は SPARQL 定式化ミスではない。** C1 の 3-hop 失敗 44 件中
   ~93% は「起点映画自身の属性を答える」(30 件; 例: 3hop-9 で起点映画の監督
   Niels_Mueller を回答)+「1〜2 ホップで停止」(11 件)。pred が起点エンティティの
   直接属性である事実は KB 照合で 100% 機械検証済み。純粋な実体リンク失敗は ≈0、
   フォーマット起因は 0。B2 も同じ誤読をする(全条件失敗 17 件中 12 件が同型)
   → 誤りは質問解釈の意味層にあり、**記号的な回答検証で機械的に検出可能**。
2. **2-hop の摂動改善(+0.2)の主因は同名衝突ではない。** C1 の摂動で直った 55 件のうち
   実際に名前衝突があるのは 6 件のみ。支配的なのは returned_pivot(25)と
   echoed_start(21)— 表層名があると「もっともらしい名前」で満足して連鎖実行を
   打ち切る挙動で、不透明 ID はそれを禁じて機械的な連鎖実行を強制する。
   なお give-up(unknown 回答)は小文字タグ実体(ns:Tom_Waits vs ns:tom_waits)への
   kb_find ヒットが原因で、これは実在する曖昧性。失敗 pred には KB に存在しない
   捏造 ID(ns:billy_chan 等)も含まれる。
3. **audit の Precision 崩壊は kb_infer の毒性。** 失敗 run の予測集合は
   OWL-RL 閉包が生む擬似違反集合と**ビット一致**(a500c5: 基底 KB の既存違反 19 件が
   functional-property 意味論で sameAs 連鎖 281 対を生み、95 件の見かけ違反に膨張。
   run 間・C1/C2 間で予測が逐語一致 = 決定論的な閉包出力の転記)。P=1.00 の run は
   kb_infer を呼ばないか kb_provenance でフィルタしている。ただし逐次 provenance
   フィルタは a500c20 で 318 呼び出し・$15.51・R=0.60 止まりと高コスト。
4. **「委譲は QA で損」(C2f 0.788)は配管バグの混入。** C2f の 51 件(8.5%)は
   `tool_calls={Agent:1}` のまま pred=null — サブエージェントの回答が自由文
   ハンドオフで失われた。null を除くと C2f = **0.862 で全条件最高**(B2 0.860 超)。
   委譲そのものは損ではない可能性が高く、修正後の再測定が必須。

補助的知見: kb_verify 使用は正答と相関(+9〜12 pt)だが使用率はホップ数と逆行
(1-hop 49% → 3-hop 12%); 失敗 run はツール呼び出しが少ない(早期の見切り、
迷走ではない); B1p の 3-hop 0.585 は切り詰め近傍に gold が入っているか
(0.857)否か(0.122)で完全に説明される(文脈の壁の直接証拠として論文に使える);
3 条件 union は 3-hop 0.915(単独最高 0.835、アンサンブル余地 +8 pt)。

## 1. 記号層の強化(S 系)

### S1. 回答バリデータ `kb_check_answer` — FINAL の記号ゲート(最優先)

新ツール(tools.py + kb.py)。FINAL を出す前に必ず通す契約(プロンプト強制、
将来的にはパースを check 通過に条件付け):

- **存在検査**: pred が KB に存在するエンティティか(捏造 ID・小文字化を即棄却)
- **型照合**: 質問の要求型(年・人物・ジャンル・映画)と pred の KB 上の型/述語位置の
  整合(例: 「when」に対し pred が year リテラル位置に現れるか)
- **起点除外検査**: マルチホップ設問で `(start, r_final, pred)` が直接成立するなら
  警告を返す(3-hop 失敗の支配モードを名指しで検出)

失敗 53 件(C1)/47 件(C2)の大半 + echoed_start/捏造 ID を直接狙う。
自己進化計画の二重ゲート(記号ゲート G1)と同型のメタ原則
「LLM の出力は決定論的検査を通ってから外に出る」の QA への適用。
起点除外は MetaQA の解答規約由来なので、論文では「設問意味論を記号検査に
コンパイルする」一般原則の実例として位置付ける(ベンチ固有ハックに見せない)。

### S2. `kb_path` — 経路探索の記号化(定式化層の置き換え)

harness.py の `neighborhood()`(距離順 BFS、B1p が使用)を kb.py に昇格し、
述語フィルタ・深さ上限・`_deadline` ガード付きでツール化:

- `kb_path(start, relation_chain, exclude_start=True)` → 連鎖に一致する
  **検証可能なエッジ列と終端集合**を返す
- ニューラルの役割は「質問 → 述語連鎖」の写像だけに縮小し、経路実行・解集合構成・
  起点除外は決定論側が担う。3-hop を B1p 並みの精度(gold-in-context 時 0.857)へ
  文脈の壁なしで到達させる筋
- symbolic-explorer(委譲側)にも配布 → ホップ毎 kb_find ループを 1 呼び出しに圧縮

### S3. `kb_infer` の毒性除去 + `kb_violations`(audit の Precision 修正)

- **閉包由来トリプルのタグ付け**: infer 後の find/sparql 結果に asserted/inferred の
  区別を付ける(閉包キャッシュは既にあるので差分は機械的に取れる)
- **新ツール `kb_violations`**: functional-property 違反を**閉包前**の主張トリプル上で
  列挙し、各違反に provenance を同梱して一括返却。318 回の provenance ループが
  1 呼び出しになり、C1 の $15 → $1 未満、P 0.05 → 1.00 の見込み
- 併せて harness `run_task`(parse_final_pairs 直後)に記号後置フィルタを挿入する
  実験変種を用意 — 「誤りは定式化層に局在」仮説の直接検証(フィルタだけで P が
  回復するなら検出は健全という主張が完成する)

### S4. verify-before-FINAL の強制

kb_verify が保護的なのに必要な場面ほど使われない(3-hop 12%)。プロンプト規律では
なくプロトコルで強制: QA_TASK に「FINAL 直前に最終ホップのトリプルを kb_verify し、
verified でなければ探索を続行」を契約化(prompt_rev 3)。S1 の check に内包させても
よい。監査側は S3 の kb_violations が同じ役割を果たす。

## 2. ハイブリッド構成の最適化(H 系)

### H1. 委譲ハンドオフの構造化(C2f バグ修正、最大のリターン)

- EXPLORER_PROMPT に「報告の末尾に `FINAL: ns:<answer>` + 根拠トリプル列」を契約化、
  QA_DELEGATE 側に「サブエージェントの FINAL を逐語コピー」を明記。
  ハンドオフを自由文からパース可能な構造に変える
- まず null 51 件だけ resume サブセットで再走(~$4)して 0.862 を確定させ、
  その後 prompt_rev 3 でフル再走の要否を判断
- **論文影響大**: 「委譲は QA で損」→「構造化ハンドオフなら委譲が最良」に主張が
  反転し得る。委譲コスト優位(監査 1/4–1/40)と合わせてハイブリッド構成の中核主張になる

### H2. 委譲の記号ルーティング(issue #8-6 の具体化)

自発委譲 0/600 の代替として、KB 規模・推定ホップ数・タスク種別による決定論的
トリガで Task 呼び出しを義務付ける。H1 の構造化ハンドオフが前提。
C2f(プロンプト強制)結果が予備データ。

### H3. 記号ゲート付きカスケード(アンサンブルの安価版)

union 0.915 の headroom を全並列($73)でなく直列で取る:
C1 が回答 → S1 の check に落ちたら B2(または kb_path 再探索)へフォールバック。
失敗は「早期見切り」型なので、棄却シグナルを返せば再探索で拾える見込み。
racing ゲート(自己進化 G2)の推論時適用でもある。

### H4. haiku 分業の拡張

記号ゲート(S1/S3/S4)が効くほど弱いモデルの誤りが外へ漏れない構造になる。
RQ5(haiku C2 = sonnet 同等 1/3 コスト)の延長で、S 系導入後に
「haiku main + 記号ゲート」の 1 列を追加測定するとコスト物語が完成する。

## 4. 論文への波及(結果を見る前に書ける範囲)

- B1p 3-hop の gold-in-context 分割(0.857/0.122)は「文脈の壁は one-shot 検索の
  構造問題」の直接証拠として §RQ2 に追加
- 「2-hop 低下 = 実体リンク曖昧性」は「表層名による満足化(satisficing)+
  タグ実体衝突」に修正(摂動で直った 55 件中、真の名前衝突は 6 件)
- 「誤りは定式化・報告層に局在」は audit で機構レベルの証拠(閉包出力の逐語転記)を
  得た。QA 側は「定式化」でなく「検証省略」(verify 使用率の逆行)として書き分ける
- C2f の結論は H1 の再測定まで保留の注記を入れる
