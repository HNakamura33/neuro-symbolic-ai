## 1. タイトル候補

1. **Symbolic Gates, Not Symbolic Tools: Making Neuro-Symbolic Layers Pay Off in LLM Agents**(記号ゲートであって記号ツールではない: LLM エージェントで記号層に元を取らせる方法)

## 2. アブストラクト(約 250 語、対訳)

> ニューロシンボリック・アーキテクチャは LLM エージェントに知識ベースと決定論的推論器を組み合わせる。記号的接地が信頼性を高めるという前提の下でである。我々は、記号層が*存在するか*よりも*どう取り付けるか*が重要であることを示す。MetaQA マルチホップ質問応答(13.3 万トリプル KB、600 問)において、記号 KB ツールを任意の道具として与えられたエージェントは完全一致 0.790 — 記号ツールを一切持たない純ニューラルな agentic-search ベースライン(0.860)を*下回る*。同一の記号的能力を出力経路上の必須ゲート — 決定論的な回答バリデータと verify-before-final プロトコル、いずれも通過しなければ解答できない — として付け直すと、精度は 0.970 に上がる(McNemar 対 search ベースライン: 判別対 66/0、p=2.7e-20)。さらにニューラルな経路探索を決定論的グラフ走査で置き換える ablation は追加の利得を生まない(0.962、p=0.3): 有効成分は探索の記号化ではなくゲートである。エラー分析がその理由を説明する: 3-hop 失敗の 93% は KB 所属・型検査が機械的に検出できる質問誤読であり、一方で保護的な verify ツールは任意である限り、最も必要な場面ほど使われない(使用率 1-hop 49% に対し 3-hop 12%)。第二の領域である KB 矛盾監査が原理を独立に確認する: 自由に参照される OWL-RL 推論器は 19 件の真の違反を 95 件の疑似違反に増幅した(Precision 0.05)が、provenance を同梱する閉包前の違反列挙器は全テストグリッドで Precision・Recall を 1.0 に回復し、コストは 75 分の 1 だった。記号層が価値を生むのはゲートとしてであり、ツールとしてではない。

*(英語版は約 248 語。投稿前に venue の正確な語数制限と照合すること。)*

## 3. 貢献(Contributions)

1. **対になった証拠を持つ設計テーゼ:** 同一の記号的能力が、任意ツールとして提供されると純ニューラルな agentic ベースラインに負け(0.790 < 0.860)、出力経路上の決定論的ゲートとして強制されると決定的に勝つ(0.970; 判別対 66/0、p=2.7e-20)。取り付け方 — ツールかゲートか — が LLM エージェントにおける記号層の貢献の符号を反転させることの、我々の知る限り初の統制された実証。
2. **有効成分を単離する ablation:** ゲートの上に決定論的経路走査(`kb_path`)を足しても有意な追加利得なし(0.962 vs 0.970、10/5、p=0.3)。利得は出力のゲートから来るのであり、探索過程の記号化からではない。
3. **設計を根拠付ける機構レベルのエラー分析:** (a) 3-hop 失敗の 93% は起点エンティティの属性誤読で、KB 検査で機械的に検出可能; (b) 任意の `kb_verify` は保護的(使用時 +9–12 pt)だが使用率がホップ数と逆転する(49% → 12%)— 助言でなく強制の動機; (c) 見かけの「委譲は QA に有害」は生存バイアス/配管アーティファクト(構造化ハンドオフ分析)であり、エージェントレベルの結論がハーネス効果に交絡され得ることの例示。
4. **KB 監査における第二領域の再現:** 矛盾を含む KB 上の OWL-RL 閉包推論器への自由アクセスは能動的に有害(sameAs 連鎖増幅、19→95 / 20→393 の疑似違反、Precision 0.05、run 間でビット同一の誤予測)である一方、ゲートされた閉包前の `kb_violations` 列挙器+provenance は全 4 グリッド × 2 エージェント構成 × 3 runs で P=R=1.0 を達成し、コストを ~$15 から ~$0.2/run に削減。
5. **非退行対照付きの回復プロトコル:** 過去に失敗したタスクのみをゲート付きプロトコルで再走して 106/126(84%)を回復、同数 126 タスクの対照群で退行ゼロ。

## 4. 論文骨子

### 4.1 はじめに
- フレーミング: 分野は記号層が LLM エージェントを*助けるか否か*を論じてきたが、答えは結合様式に依存することを示す。任意ツール → エージェントは負荷が高い場面ほど使わず、純ニューラル探索に負ける。必須ゲート → 大差かつ統計的に決定的な勝利。
- テーゼ文: *任意ツールとして取り付けられた記号層は純 LLM の agentic システムに負ける。同じ層を出力経路上の必須ゲートとして取り付ければ大差で勝つ。*

### 4.2 システム
- LLM エージェント+永続 RDF/OWL KB; ツール群(`kb_find`、`kb_sparql`、`kb_verify`、`kb_infer`); 2 つのゲート: `kb_check_answer`(存在・質問との型整合・起点除外 — 「設問意味論を記号検査にコンパイルする」ものとして提示)と verify-before-FINAL プロトコル; 監査用 `kb_violations`(閉包前列挙+provenance 同梱); asserted/inferred タグ。

### 4.3 実験 1 — マルチホップ KGQA(主結果)
- MetaQA、133,582 トリプル、600 問(hop 毎 200)、完全一致、キー `correct`。
- 条件: B0(KB なし)、B2(agentic-grep、記号ツールなし)、C1-rev2(記号ツール任意)、C1-rev5(ツール+ゲート)、C1-rev6(rev5 + `kb_path` ablation)。
- 結果表: 0.193(B0)/ 0.860(B2、hop 別 .935/.810/.835)/ 0.790(rev2、.905/.685/.780)/ **0.970(rev5、.950/.980/.980)** / 0.962(rev6、.950/.990/.945)。McNemar: rev5 vs B2 66/0 p=2.7e-20; rev5 vs rev2 108/0 p=6.2e-33; rev5 vs rev6 10/5 p=0.3。
- 補強証拠としての汚染プローブ: エンティティ ID 摂動で B0 は 0.000 に崩壊、記号条件はほぼ不変 — KB は本当に参照されており、暗記ではない。
- 失敗タスク回復: 106/126(84%)、対照 0/126 退行。

### 4.4 実験 2 — 矛盾監査(第二領域)
- 2×2 グリッド({500,2000} 主張 × {5,20} 矛盾)、3 runs、C1/C2。
- 修正前: Recall ≈1.0 だが Precision は双峰で 0.05 に崩壊; 機構: 矛盾 KB 上の OWL-RL 閉包が sameAs 連鎖の疑似違反を製造し、エージェントがそれを逐語転記(run 間ビット同一の予測)。トリプル単位の provenance 修復: 318 呼び出し、$15.51、R=0.60。
- 修正後(`kb_violations`): 全 24 runs で P=R=1.0、≈$0.2/run。
- 読み方: 監査結果はゲートテーゼの対偶 — *ゲートされていない*記号推論器は無いより悪くなり得る。

### 4.5 エラー分析
- 3-hop 失敗: ~93% が起点エンティティの属性誤読(KB と機械的に照合済み); ニューラルベースラインとも共有(全条件失敗 17 件中 12 件で同じ誤読)→ 誤りは質問解釈にあり、記号的に検出可能。
- 任意 verify の使用率逆転(hop 別 49%/…/12%)と条件付き利得 +9–12 pt。
- 2-hop の摂動利得(+0.2)は表層名満足化(returned-pivot / echoed-start)に由来し、エンティティ衝突ではない(6/55)。
- 委譲の注意書き: 「強制委譲は有害」はハンドオフバグ(8.5% の null 解答)が駆動していた; null を除くと委譲は競争的 — 方法論的な教訓として報告。[TODO: 本文執筆時までに H1 構造化ハンドオフ再走が完了している場合のみ収録; アブストはこれに依存しない。]

### 4.6 関連研究
- **LLM+形式ソルバ**(Logic-LM、LINC、SatLM、Proof of Thought、MCP-Solver): LLM が定式化しソルバが判定する — ただしエピソード毎で、ソルバは呼び出し可能な道具。ツール vs ゲートの取り付け様式や矛盾 KB の失敗事例を研究したものはない。
- **自己検証 / self-refine**(Chain-of-Verification、SelfCheckGPT、self-consistency): 検証器が LLM 自身のため、検証が生成器の失敗モードを継承し、厳格な前提条件にできない。我々の差別化: 検査が**決定論的かつ記号的**(KB 所属、型位置、provenance)で、強制可能な二値判定を返す。FormalJudge(Dafny/Z3 監督)が最も近い形式ゲートの親戚; KG-Guard(KBQA の事後接地性検出)は検出器であり、我々のは構成的かつインライン。
- **KG エージェント推論**(Think-on-Graph、SymAgent、EmbedKGQA 系譜): 推論主体は LLM のままで、記号構造は探索を誘導するのであって出力をゲートしない。
- **形式的主張を持つエージェントメモリ**(Kumiho、Zep、WorldDB、TOKI; STALE/Supersede/DeltaLogic 測定): 永続化と改訂は形式化されるが、解答時の検証はニューラルのまま — 相補的な動機付け。
- 位置付けの一文: 従来の NeSy 研究は記号層が*何を*計算するかを問うてきた。我々はそれがエージェントループの*どこに*結合するかを問い、結合部位が支配的であることを示す。

### 4.7 限界(誠実に)
- **claim 検証 RQ の飽和:** 合成 claims では自明でない全条件(KB 全文貼り付け含む)が全スケールで 1.000 となり判別不能。テーゼの証拠には使わず null として報告。推論必須 claims への agentic-search ベースラインは今後の課題。
- **ベンチマーク構造がニューラルベースラインに有利で、ゲートの形も規定する:** MetaQA はエンティティが逐語で現れ KB テキストが行指向(grep 向き)。ゲートの一成分(起点除外)は MetaQA の解答規約のコンパイルであり、「設問意味論の検査へのコンパイル」の MetaQA 外への一般性は未検証。
- **単一モデル系列・限られたシード:** QA の見出し数値は Sonnet 級 1 モデル・条件毎単一 run+対応あり McNemar。監査は 3 runs/セル。安価モデルでの再現を計画中。
- **合成監査 KB**(≤2000 主張、注入違反); そこでは全文脈ベースラインも P/R 1.0 のため、監査の貢献は機構とコストであり見出し精度ではない。
- ゲートはコストを上げる(600 問あたり ~$38 vs ~$21–22): 精度/コストのトレードオフは明記すべき。

### 4.8 結論
- テーゼ再掲; レシピ(出力をゲート、閉包前に列挙、全判定に provenance); 今後: ゲート付きカスケード(3-hop の union 上限 0.915)、安価モデル+ゲート構成、自己進化の二重ゲートとの接続。
