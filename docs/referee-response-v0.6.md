## Major concerns

### M1. 中心主張が開発と同一の 600 問で測られている(適応的過学習の危険)

> 開発に一切使っていない新規サンプルでの rev5 の再測定が必須。摂動版も rev2 系でしか走っていない。解消されない限り 0.970 は「開発セット上の値」として割り引かざるを得ない。

**新規実験で回答した。** 開発に一切用いていない held-out 600 問を構築し、rev5 を凍結worktreeから無改変で再測定した。

- **構築**: `data/metaqa-heldout` — MetaQA test split の同一分布から seed 7 で各ホップ 200 問(計 600)を新規サンプリング。benchloader の `--exclude` で開発用 600 問を全除去し、**重複ゼロを検証**。`kb.ttl` は開発セット `data/metaqa` と **sha256 バイト同一**(KB は共有、質問集合のみ非重複)。摂動版 `data/metaqa-heldout-pert` は開発摂動セットと同一の全単射・不透明 ID リネーム手続き(perturb seed 42)で生成。
- **rev5 held-out**: EM **.950 / .990 / .990、total 0.977**(cost $28.52、error 0)。開発セット rev5 は .950/.980/.980、total 0.970。**held-out は全ホップで同等以上**であり、適応的過学習の割引は不要。
- **held-out 上の対応あり比較**: rev5 vs B2(同一 600 問)= **61/5、p=2.63e-13**(開発は 66/0、p=2.71e-20)。分離は未使用データ上で再現した。B2 held-out は .950/.815/.885、total 0.883(開発 B2 = .935/.810/.835、total 0.860。2-hop は .815 vs .810 とほぼ完全に再現)。
- **摂動 held-out rev5**: .870/.975/.815、**total 0.887**(cost $82.16、error 0)。rev2 系の摂動 C1(開発)0.802 に対し、ゲートは摂動下でも **+.085** の優位を保つ。同一質問の原名 vs 摂動対応あり比較 = 63/9、p=4.18e-11 で、摂動は 1-hop(エンティティリンク)と 3-hop(長鎖探索)で依然として実精度を奪い、探索コストは 3 倍($28.52→$82.16)になる。

**誠実な枠組み**: ゲートの優位は held-out・摂動下でも保たれる(絶対 EM は .977→.887 に低下)。**残る限界**として、ゲート設計自体は開発セットの誤り分析に基づいて行われた点、および今回は同一ベンチマークの held-out であって cross-benchmark の汎化ではない点を §7 に明記した。後者は future work とする。

### M2. 「真の違反 19 件が 95 件に」は生データと整合しない(Abstract 級)

> a500c5 の gold は 5 件(`data/a500c5/injected.jsonl` = 5 行)。P=0.05 ≈ 5/95。rev4 は正確に 5 件を返し P=R=1.0。「19」は内部ノート由来と推察。5→95 に修正を。

**修正した。** `data/a500c5/injected.jsonl` が **5 行**であること、崩壊 run の collapsed preds が 86/95/86、rev4 が正確に gold=5 を返すことを再確認した(査読者の独立再計算と一致)。Abstract・貢献4・§4.3・§5.3 の記述を「真の違反 **5 件 → 95 件**(増幅率 **19 倍**)」に統一した。「19」は増幅率(95/5)を、内部ノート(`design-revision-plan.md`)から件数として転記した誤りであった(**これは Q1 への回答でもある**)。大グリッドの「20→393」は正確なので据え置き。

### M3. 「決定論的ゲート」と「強制検査プロトコル一般」が MetaQA 上で分離されていない

> B2+強制再検査契約(ニューラル版ゲート)のアブレーションがあれば利得を分離できるが無い。§4.4 のネガコンは別ドメイン。この 1 条件を追加するだけで貢献1は大幅に強化される。

**新規アブレーション B2g で回答した。** rev5 の記号ゲート手順をステップごとに grep で模したニューラル版ゲートを追加した。

- **B2g の定義**: B2(Grep/Read のみ、kb_* ツールなし)+ 強制 grep ベースの verify-before-FINAL 契約(`experiments/harness.py` の `QA_GREP_VERIFY`)。契約は rev5 ゲートを鏡写しにする — (a) 最終ホップ辺を `kb.ttl` 上で grep で両方向確認、(b) 候補の存在検査 + 起点除外検査 + 連鎖の再導出。**既存プロンプトは一切変更せず**(rev-6 era のコードで実装)。
- **B2g(原版 600)**: .945/.945/.960、**total 0.950**(cost $30.72、error 0)。
- **分解(対応あり McNemar、原版 600)**:
  - **B2g vs B2 = 59/5、p=9.0e-13 → 「プロトコル強制」成分 +.090**。
  - **rev5 vs B2g = 18/6、p=0.0227 → 「決定論的検査器」成分 +.020**(小さいが有意、方向一貫)。
- **論文への反映**: 査読者の代替仮説は**部分的に正しかった** — ツール→ゲート利得の大半はニューラルに実装可能な「出力経路上の検証プロトコル強制」由来である。ただし決定論性は**その上に有意な残差を上乗せする**。貢献1を「結合様式が符号を反転させる」から、より鋭い**分解された主張**(プロトコル強制が主効果、決定論性が有意な残差)へ書き換えた。**これは M3 を議論でなくデータで回答するものであり、Q4 への回答も兼ねる。**

### M4. ネガティブコントロール(4c)は検出力不足で、Abstract の断定はデータより強い

> 19/20 vs 15/20、片側 p=0.0909。n=20 では 20 ポイント改善すら検出できない。逐次デザイン(初期 5 問後に 15 追加)の補正なし。n を増やす/検出力と CI を併記して主張を弱める/逐次デザインを明記。

**ドラフト上で主張を弱め、デザインを開示した。** 検出力分析(power 0.38)と 95%CI **(−0.03, +0.42)** を併記。Abstract・§8 の「ゲートの有効成分は決定論性でありセカンドオピニオンではない」を、**「n=20 では判定者の利得は検出されず、効果があるとしてもモデル間差(p=2.9e-08、頑健)より一桁小さい」**へ改訂した。逐次デザイン(初期 5 問で分離を見た後に 15 問を追加設計したこと)を §4.4 に明記した(**Q5 への回答**)。n 拡大は cost の理由で future work とする。

### M5. 見出し条件が単一 run であることは、本論文自身の証拠(監査の双峰性)で危うくされている

> 最低限 rev5 と B2 だけでも 3 run 化し、run 間 EM 変動幅を報告すべき。

**各条件 3 run で回答した。**

- **C1-rev5**: 0.970 / 0.970 / 0.973(mean **.971**、range .003)。ホップ別 run 間: 1-hop .945–.950、2-hop .980–.985、3-hop .980–.990。
- **B2**: 0.860 / 0.850 / 0.863(mean **.858**、range .013)。
- rev5–B2 の差 **.113 は最大の run 間変動の約 10 倍**であり、監査ドメインで見られた双峰性は MetaQA のゲート条件には現れない。
- **脚注に付す注意**: B2 の run1/run2 レコードは prompt_rev=6(現 main)を持つが、B2 のプロンプト本文は rev2 以降不変(rev 3–6 は C1/C2/C2f/監査プロンプトへの追記のみ)であり比較可能性に影響しない。rev5 追加 run は凍結 `PROMPT_REV=5` worktree から起動し、全レコード prompt_rev=5 を検証済み。

### M6. 表4 の B2 行「原版との差 −.063」は分母の異なる集合を比較している

> 摂動 B2 は 300 問。同一 300 問に揃えた対応あり比較では原版 .833、差は −.037(ホップ別 −.090/+.140/−.160)。マッチ部分集合で再掲を。

**修正した。** 表4 の B2 行を**マッチした同一 300 問**での対応あり比較(原版 .833、摂動 .797、**差 −.037**)に差し替え、ホップ別デルタ(1-hop −.090、2-hop +.140、3-hop −.160)を併記。ホップごとに符号が逆になる点を McNemar 注で明示した。B2 のみ 300 問である理由(摂動セットは各ホップ 100 問構成)を本文に明記した。頑健性という結論は保持。

## Questions to authors(明示回答)

**Q1. 「19 件」の出所は?** — 増幅率(95/5=19 倍)を内部ノート `design-revision-plan.md` から件数として転記した誤り。M2 で修正済み(gold=5、`data/a500c5/injected.jsonl` 5 行で確認)。

**Q2. rev5 の凍結は全 600 再走の前か? タイムラインは?** — **前である。** rev5 のプロンプト・ゲート仕様は Lane F マージ commit **`55df292`("Merge lane F: kb_check_answer + verify-before-FINAL, prompt_rev 5")で凍結**され、その**後**に失敗126 再走(`680e524`)→ 対照126 → 全600 が走った(`git log --oneline` で順序確認済み)。本改訂の held-out 各 run はこの凍結 worktree を無改変で再利用した(検証: `cd .claude/worktrees/rev5-pin && git log --oneline -3` の HEAD が 55df292 を含む系列であること)。

**Q3. 摂動・新規サンプルで走らせない理由(コスト以外)は?** — **コスト以外の理由はない。** 今回すべて実行し、結果は M1 の通り(held-out rev5 0.977、摂動 held-out 0.887)。

**Q4. B2 に verify-before-FINAL 相当を課した予備データはあるか?** — M3 の B2g がそれである。B2g 0.950、分解でプロトコル成分 +.090(p=9e-13)・決定論成分 +.020(p=0.023)。

**Q5. 4c の tier 設計は初期 5 問の結果を見た後か?** — **その通り(逐次デザイン)。** 初期 5 問で分離を見た後に 15 問を追加設計した。§4.4 に開示し、検出力(0.38)と CI を併記して主張を弱めた(M4)。

**Q6. `kb_check_answer` の型照合・存在検査は KB スキーマにどの程度依存するか?** — **存在検査・型照合は汎用 RDF** で無改変移植可能。**起点除外成分のみ MetaQA の解答規約を符号化**しており、§1.1/§7 でその旨を宣言している。したがって移植性 = 存在・型部分は generic、規約層はベンチマーク固有。
